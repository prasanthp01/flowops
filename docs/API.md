# FlowOps HTTP and schema contracts

Public prefix: `/api/projects/flowops`. All inputs are synthetic. The browser never supplies a model key or connector URL.

| Method and suffix | Contract |
| --- | --- |
| `GET /health` | Database-backed readiness; non-200 during a database outage |
| `POST /session` | Exact configured Origin required; returns CSRF token and sets HttpOnly, SameSite=Strict cookie |
| `GET /simulation/schema` | Bounded project input/request schemas and resource limits |
| `GET /simulation/presets` | Five editable synthetic inputs |
| `POST /simulations` | Session + Origin + CSRF + 8–64 character Idempotency-Key; atomically persists run/work marker; returns 202 |
| `GET /simulations/{id}` | Owner/environment-checked lifecycle and provenance |
| `GET /simulations/{id}/events` | SSE with monotonic numeric IDs; supports Last-Event-ID and `after` |
| `GET /simulations/{id}/events?format=json&after=N` | Ordered polling; duplicate/out-of-order clients can deduplicate by sequence |
| `GET /simulations/{id}/result` | Shared v1 envelope; outcome and extended provenance inside `output` |
| `POST /simulations/{id}/cancel` | Owner + Origin + CSRF; terminal transition fences old workers |
| `GET /operator/simulations/{id}` | Private bearer-authenticated inspection for the configured environment |
| `POST /operator/simulations/{id}/approval` | Private bearer auth, exact request ID, action digest and approve/reject decision |

Cookies use `Secure` whenever the configured origin is HTTPS. Non-local/test configurations reject HTTP origins. Session signatures and CSRF tokens bind the environment. Each run lookup checks owner and environment; knowing the UUID grants no access. Raw credentials, rejected input and validation exception contents are not echoed in API errors. Stable codes include `INVALID_INPUT`, `SESSION_REQUIRED`, `CSRF_DENIED`, `RUN_NOT_FOUND`, `RUN_EXPIRED`, `RATE_LIMITED`, `APPROVAL_BINDING_MISMATCH` and `INTERNAL_ERROR`.

An idempotency key replay returns the original run only for the same validated request. Reuse with different inputs returns 409. Run concurrency is capped at 64 globally and 3 per session; starts are capped at 30/minute/session, 120/minute/IP pseudonym and 240/minute globally. Signed-session minting is capped at 120/hour/IP pseudonym and 1000/hour globally. Reads are capped at 600/minute/session. Database locking serializes admission/counter updates. Forwarded IP headers are not trusted; behind a proxy, the visible connection IP is shared unless a reviewed edge policy is introduced.

SSE is bounded to two slots per session and 32 total, 10 seconds per connection, with 15-second slot expiry after a process crash. The client deduplicates by sequence and also polls to recover stream loss. HTTP request bodies are bounded to 16 KiB and a five-second receive deadline. The ASGI application and Uvicorn cap in-flight work; these bounds are not a substitute for edge DDoS controls.

Run statuses are lifecycle values from the baseline contract. Business outcomes live separately under `outcome` / `output.outcome`. `APPROVAL_PENDING` does not imply a running leased worker. `SUCCEEDED` with `BLOCKED` means the investigation successfully concluded that the action was forbidden. Client `existing_approvals=untrusted_claim` is scenario data, never authorization.

The supplied baseline schemas remain in `contracts/baseline`. Extended typed schemas in `schemas/` are generated by `scripts/export_schemas.py`. Structured specialist outputs are validated before downstream consumption. Required provenance extensions use the baseline's allowed `technical` and `output` objects rather than adding forbidden top-level fields.

## Real-model integration status

Only `SANDBOX_DETERMINISTIC` is admitted at the public endpoint. Recorded browser history is explicitly labeled as a recorded view of an original run; there is no prerecorded response masquerading as fresh computation. Authenticated live-model execution is not exposed in this release. `InferenceRequest` is compatible with the supplied AgentOps v1 metadata schema; content, response shape, endpoint, credential audience, pricing and budget-reservation compatibility remain to be agreed and tested with AgentOps.
